## 1. 项目概述

### 1.1 项目名称

情绪周期选股系统（Emotion Cycle Screener，简称 ECS）

### 1.2 项目定位

面向 A 股短线交易者的**情绪周期分析与选股辅助工具**。通过量化市场情绪指标，自动判定情绪周期阶段，为交易者提供可核对的盘面读数和操作建议，将"凭感觉交易"转变为"按数据决策"。

### 1.3 核心价值

- **可核对**：每个情绪判断都有明确的数据支撑，不再是"我觉得"
- **有纪律**：五阶段对应明确的动作倾向，帮助克服交易心理偏差
- **可回溯**：历史周期数据存档，支持复盘和规律总结
- **零依赖**：单文件 HTML，双击即用，无需安装任何软件

### 1.4 目标用户

- A 股短线交易者（打板、接力、低吸）
- 希望建立系统化交易纪律的投资者
- 对市场情绪周期理论感兴趣的学习者

## 2. 需求背景

### 2.1 问题陈述

A 股短线交易中，**情绪周期**是决定盈亏的核心变量。然而：

1. **情绪不可直接观测**：交易者往往凭"感觉"判断市场冷热，缺乏可量化的代理指标
2. **指标分散**：涨停家数、跌停家数、红盘率、封板率、晋级率等数据散落在不同软件中，难以综合判断
3. **阶段易误判**：将反弹当修复、将退潮当冰点、只看涨停家数不看广度等误判频繁发生
4. **执行率低**：即使判断正确，也常因心理偏差未能执行对应操作
5. **复盘无体系**：每日复盘缺乏标准化流程，经验难以沉淀

### 2.2 理论来源

本系统基于"满仓长红"《情绪周期七课》理论体系，核心要点：

- 情绪通过**四个脚印**可观测：涨停家数、跌停家数、红盘率、封板率/晋级率
- 情绪周期分为**五个阶段**：冰点 → 修复 → 升温 → 高潮 → 退潮
- **四步判读法**：家数 → 广度 → 接力 → 高度，顺序不能乱
- **温度量化**：将多维度指标加权合成为 0-100 的温度值
- **动作对应**：每个阶段有明确的动作倾向（等/试/上/收/退）

### 2.3 需求目标

构建一个**单文件、零依赖、可离线运行**的 Web 应用，实现：

1. 自动计算情绪温度并判定周期阶段
2. 可视化展示四个脚印指标和温度趋势
3. 提供五阶段对应的选股策略和条件
4. 标准化每日复盘流程并自动存档
5. 支持历史周期回溯和规律总结
6. 数据本地存储，支持导入导出

## 3. 核心理论

### 3.1 四个脚印（情绪代理指标）

| 指标 | 定义 | 含义 | 观测要点 |
|------|------|------|---------|
| **涨停家数** | 当日收盘封住涨停的股票数量 | 有多少钱愿意往上冲 | 看相对变化，不看绝对值 |
| **跌停家数** | 当日收盘封住跌停的股票数量 | 有多少钱在夺路而逃 | 比涨停更早暴露恐慌 |
| **红盘率** | 上涨家数 ÷ 全部交易家数 | 全市场是涨多还是跌多 | 区分结构性行情与普涨 |
| **封板率** | 曾涨停中收盘仍封着的比例 | 封单愿不愿意守住 | 反面是炸板率 |
| **连板晋级率** | 昨日涨停今日仍涨停的比例 | 接力愿不愿意往上做 | 跨日持续性指标 |
| **首板晋级率** | 昨日首板今日晋级二板的比例 | 接力资金的早期态度 | 长期均值约 16% |
| **最高连板** | 当日涨停梯队中连板数最高的身位 | 塔尖高度 | 结果非原因，用于验证 |

### 3.2 五个阶段

```
冰点 → 修复 → 升温 → 高潮 → 退潮 →（回到冰点）
```

| 阶段 | 温度区间 | 核心特征 | 动作倾向 | 仓位建议 |
|------|---------|---------|---------|---------|
| **冰点** | < 30° | 连板高度压到2-3板，涨停少，跌停冒头，红盘率低，封板率低，晋级率极低 | **等** | 空仓或极小仓(≤10%) |
| **修复** | 30-55° | 成交缩量，跌停明显减少，有票试探性上冲，资金还不敢放开 | **试** | 轻仓(20-30%) |
| **升温** | 55-75° | 涨停家数变多，连板高度往上拱，昨日涨停今天能接着涨，赚钱效应回来 | **上** | 正常仓位(50-70%) |
| **高潮** | > 75° | 满屏涨停，连板高度拉满，闭眼买都赚钱 | **收** | 减仓(≤30%)，只减不加 |
| **退潮** | 高位下降 | 高位标滞涨，炸板增多，前一天香饽饽今天按跌停，赚钱效应消失 | **退** | 空仓或极低仓(≤10%) |

### 3.3 四步判读法

顺序不能乱：**家数 → 广度 → 接力 → 高度**

1. **第一步 家数（多不多）**：看涨停家数的相对变化，仅作参考不下结论
2. **第二步 广度（面宽不宽）**：看红盘率、涨跌家数比，区分结构性与普涨
3. **第三步 接力（有没有下文）**：看晋级率，最关键也最易判错，需跨天数据
4. **第四步 高度（塔尖稳不稳）**：看最高连板，结果非原因，用于验证判断

### 3.4 关键规律

- **升得慢，退得快**：升温需数天积累，退潮往往1-2天完成
- **高度先掉，广度后崩，跌停最后爆**：高潮转退潮有先后顺序
- **退潮第2天比第1天更危险**：亏钱效应往昨天的高位票补刀
- **首板晋级率低于16%是接力资金撤离的早期信号**
- **第二个高标没能超过第一个高度时，不要期待第三个**

### 6.2 技术选型

| 层级 | 技术 | 版本 | 用途 |
|------|------|------|------|
| 结构 | HTML5 | - | 页面结构 |

### 6.3 设计决策

1. **单文件架构**：所有 HTML/CSS/JS 打包在一个文件中，便于分发和使用
2. **无前端框架**：使用原生 JS，减少依赖和体积，提高加载速度
3. **CDN 引入库**：Tailwind 和 Chart.js 通过 CDN 引入，首次加载后可缓存
4. **LocalStorage 存储**：数据完全本地存储，保护隐私，无需后端
5. **可插拔数据层**：支持手动录入、JSON导入、Python脚本采集三种数据来源

## 8. 核心算法

### 8.1 情绪温度计算

**公式**：

```
温度 = (涨停家数得分 × W1 + 跌停家数得分 × W2 + 红盘率得分 × W3
     + 封板率得分 × W4 + 晋级率得分 × W5 + 最高连板得分 × W6) / ΣW
```

**各维度归一化**：

| 维度 | 归一化方式 | 默认权重 |
|------|-----------|---------|
| 涨停家数 | min(100, 涨停数 / 150 × 100) | 20% |
| 跌停家数 | max(0, 100 - 跌停数 / 30 × 100)，反向 | 15% |
| 红盘率 | 直接使用百分比 | 20% |
| 封板率 | 直接使用百分比 | 15% |
| 晋级率 | min(100, 晋级率 / 60 × 100) | 15% |
| 最高连板 | min(100, 连板数 / 10 × 100) | 15% |

**设计说明**：
- 涨停家数 150 家为满格（A股历史极端行情约 150-200 家）
- 跌停家数 30 家为零分（超过 30 家属于极端恐慌）
- 晋级率 60% 为满格（历史最高约 57%）
- 最高连板 10 板为满格（A股罕见超过 10 板）

### 8.2 阶段判定算法

```
if 温度 < 30:
    阶段 = 冰点
elif 30 <= 温度 < 50:
    if 有昨日数据 and 跌停减少 and 涨停回升:
        阶段 = 修复
    elif 有昨日数据 and 跌停增加:
        阶段 = 退潮
    else:
        阶段 = 修复
elif 50 <= 温度 < 70:
    阶段 = 升温
elif 70 <= 温度 < 85:
    if 有昨日数据 and 温度下降:
        阶段 = 退潮
    else:
        阶段 = 高潮
else:  # 温度 >= 85
    阶段 = 高潮
```

### 8.3 选股综合评分

```
基础分 = 50
+ 连板数 × 5          （连板越高分越高）
+ 换手率适中 +15       （5%-20%为适中，>20%扣5分）
+ 量比 > 1.5 +10
+ 主力净流入 > 0 +10
+ 封单 > 5000万 +10
+ 市值 50-200亿 +10   （适中市值加分）
最高分 = 100
```

### 8.4 转折点识别

| 事件类型 | 触发条件 |
|---------|---------|
| 暴力反弹 | 单日温度变化 ≥ +20° |
| 断崖退潮 | 单日温度变化 ≤ -20° |
| 阶段切换 | 当日阶段 ≠ 昨日阶段 |

## 11. 数据采集

### 11.1 自动采集脚本

项目提供 `data_collector.py` 脚本，可自动从 AKShare 获取 A 股每日行情数据。

**安装依赖**：

```bash
pip install akshare pandas
```

**运行采集**：

```bash
python data_collector.py
```

**输出**：在 `data/` 目录下生成 `emotion_YYYY-MM-DD.json` 文件，可直接导入网页应用。

### 11.2 采集数据项

| 数据项 | 来源 | 说明 |
|--------|------|------|
| 涨停股票列表 | AKShare 涨停板行情 | 含代码、名称、连板数、封单、换手率等 |
| 跌停股票数量 | AKShare 跌停板行情 | 统计当日跌停家数 |
| 涨跌家数 | AKShare A股实时行情 | 统计全市场上涨/下跌家数（排除北交所） |
| 红盘率 | 计算得出 | 上涨家数 / 总交易家数 |
| 封板率 | 估算得出 | 有封单的涨停股占比 |
| 晋级率 | 估算得出 | 连板股占涨停股比例 |

### 11.3 数据口径

- 含 ST，不含北交所（代码 8 开头）
- 以收盘定版数据为准
- 涨停判定：收盘价 = 涨停价 且 收盘有封单

### 11.4 手动录入

如果不使用自动采集脚本，可在「数据设置」页面手动录入每日核心指标：

1. 涨停家数、跌停家数
2. 上涨家数、下跌家数（自动算红盘率）
3. 曾涨停数、封住涨停数（自动算封板率）
4. 连板晋级率、首板晋级率
5. 最高连板数
